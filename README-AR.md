# ميري ايران V6: الخطوة 1 (الخلفية + Charter724)

**مهم، اقرأ أولاً:**
- هذه النسخة تضيف **الخلفية (Node.js) فقط**: تسجيل الدخول بخطوتين، قائمة المطارات، البحث عن الرحلات (ذهاب فقط أو ذهاب وعودة).
- **لم تُجرَّب مع خادم Charter724 الحقيقي.** كل الاختبارات التي نجحت تستخدم ردوداً وهمية مبنية على ملف المواصفات (OpenAPI). النجاح فيها يعني أن كودنا يتبع التوثيق، ولا يثبت أن الخادم الحقيقي يتصرف كذلك.
- **الواجهة الأمامية لم تتغير** (نفس V5) وما زالت تعرض نتائج تجريبية.
- **الحجز والدفع وإصدار التذاكر والاسترداد معطّلة** ولا يوجد أي كود يتصل بمساراتها.

## 1) تثبيت Node.js (مرة واحدة)
1. افتح https://nodejs.org وحمّل نسخة **LTS** وثبّتها.
2. أغلق PowerShell وافتحه من جديد، ثم اكتب:
```powershell
node -v
```
يجب أن يظهر رقم 18 أو أعلى. لا حاجة لـ `npm install` لأن المشروع بلا اعتمادات.

## 2) الدخول إلى المجلد
فك ضغط `miri-iran-v6-step1.zip` ثم:
```powershell
cd $HOME\Downloads\miri-iran-v6-step1
```
(غيّر المسار حسب مكان فك الضغط.) إذا قال PowerShell إن `npm` ممنوع، استخدم `npm.cmd` بدلاً من `npm` في كل الأوامر.

## 3) تشغيل الاختبارات (لا تحتاج إنترنت ولا حساب)
```powershell
npm test
```
النتيجة الصحيحة: `20 passed` ثم `14 passed, 0 failed` ثم `19 passed, 0 failed` ثم `32 passed, 0 failed`.

## 4) تشغيل الموقع (وضع تجريبي)
```powershell
Copy-Item .env.example .env
npm start
```
افتح http://127.0.0.1:3000 في Chrome. للإيقاف اضغط `Ctrl + C`.
تحقق أيضاً من: http://127.0.0.1:3000/api/health (يجب أن يظهر `"mode":"demo"`) و http://127.0.0.1:3000/api/airports (قائمة تجريبية).

## 5) فحص الاتصال الحقيقي بـ Charter724 (للخطوة 2، قراءة فقط)
1. افتح ملف `.env` بالمفكرة:
```powershell
notepad .env
```
2. اكتب اسم المستخدم في السطر `CHARTER724_USERNAME` وكلمة المرور في السطر `CHARTER724_PASSWORD` (بعد علامة المساواة مباشرة، بدون مسافات ولا علامات اقتباس) واحفظ. **لا ترسل كلمة المرور لأحد ولا ترفع `.env` إلى GitHub.**
3. شغّل:
```powershell
npm run check:live
```
أو لمسار وتاريخ محددين (التاريخ يجب أن يكون اليوم أو بعده):
```powershell
npm run check:live -- MHD KIH 2026-12-01
```
4. سيطبع البرنامج 5 خطوات: الإعدادات، عنوان IP الذي يراه Charter724، تسجيل الدخول، قائمة المطارات، ثم بحث تجريبي. **لا يطبع كلمة المرور ولا التوكن**، ويستدعي مسارات القراءة فقط. انسخ النتيجة كاملة وأرسلها لي.
5. حسب المواصفات، الحسابات غير التجريبية يُتحقق منها مقابل IP. إن فشل الدخول أو البحث برسالة عن التوكن، فقد يكون السبب أن IP جهازك غير مسجّل لدى Charter724. عنوان IP يظهر في الخطوة 2، واطلب منهم تسجيله. وبما أن IP البيت قد يتغير، فقد يتوقف الاتصال لاحقاً.
6. حساب `demo/demo` مذكور في المواصفات "إن كان مفعّلاً على الخادم"، ولا أعرف إن كان مفعّلاً.

## 6) تجربة مسارات الخادم المحلي في الوضع الحقيقي (اختياري)
في `.env` غيّر `APP_MODE=demo` إلى `APP_MODE=live` ثم `npm start`، وفي نافذة PowerShell ثانية (استبدل التاريخ بتاريخ قادم):
```powershell
Invoke-RestMethod http://127.0.0.1:3000/api/airports | ConvertTo-Json -Depth 5
$b = @{ from='MHD'; to='KIH'; date='2026-12-01'; adults=1 } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:3000/api/flights/search -ContentType 'application/json' -Body $b | ConvertTo-Json -Depth 6
```
للذهاب والعودة أضف `trip='round'; returnDate='2026-12-05'`. لدرجة الأعمال أضف `cabin='business'`. تذكير: صفحة الموقع نفسها ما زالت تعرض نتائج تجريبية لأن ربط الواجهة هو الخطوة 3.

## 7) ما الذي أنجزته هذه الخطوة
- **المصادقة:** `userPassBase64` ثم `Login`، والتوكن يُخزَّن ويُجدَّد حسب `expires_Utc` (بحد أقصى 24 ساعة)، وعند الرد 401 (`-105`) يُعاد الدخول مرة واحدة فقط.
- **رسائل الأخطاء:** تُقرأ شيفرة `Msg` الموثّقة: `-203` تاريخ قديم، `-105` توكن مرفوض (وقد يكون IP غير مسجّل)، `-104` فشل الدخول، `422 validation`. كل رسالة تحمل `providerCode`.
- **`/api/airports`:** من `Airportlist`، مع حذف الرموز غير الصالحة والمكررة وتخزين مؤقت 6 ساعات.
- **البحث:** ذهاب فقط = طلب واحد. ذهاب وعودة = طلبان (يوم الذهاب ثم يوم العودة) وقائمتان منفصلتان `results` و`returnResults`.
- **الدرجة:** تُصنَّف من `type_flight` و`DisplayLable` (اقتصادية/أعمال). الرحلات من درجة أخرى أو ذات تسمية غير مفهومة تُستبعد وتُحصى في `meta`، ولا تُعرض بدرجة خاطئة أبداً.
- **الأسعار:** الإجمالي = سعر البالغ × العدد + سعر الطفل × العدد + سعر الرضيع × العدد (الأسعار الحقيقية من الـ API، لا النسب التجريبية). الريال ÷ 10 = تومان، والمبلغ الأصلي محفوظ. تُستبعد الرحلات ذات السعة 0 أو المقاعد غير الكافية (الرضّع بلا مقعد) أو بلا سعر للطفل/الرضيع المطلوب أو بعملة غير معروفة.
- **معرّفات الرحلات:** `id` ثابت وفريد، و`providerRef` يحفظ الحقول التي سيحتاجها الحجز لاحقاً (ajency_online_ID وغيرها). الحجز نفسه غير منفَّذ.
- **التاريخ:** "اليوم" يُحسب بتوقيت طهران (`TIMEZONE=Asia/Tehran`).

## 8) ما لم يُختبر وما يجب التحقق منه في الخطوة 2
- **كل شيء مع الخادم الحقيقي:** لم أتصل به أبداً (لا إنترنت في بيئتي). اختباراتي كانت على Node 22 في Linux وليس على جهازك.
- **تسميات الدرجات:** المواصفات تعطي مثال `Economy`/`اکونومی` فقط. تسمية الأعمال عندي افتراض (`Business`/`بیزینس`). ما لا يُفهم يُستبعد ويظهر في `meta.unclassifiedCabins`، وفحص `check:live` يطبعه لتصحيح القائمة.
- **عملة الأسعار:** أتوقع `IRR`. أي عملة أخرى تُستبعد ولا تُحوَّل.
- **معنى الرموز `-104` و`-404`:** المواصفات تذكر وجودها ولا تشرح معناها، لذلك الرسائل عنها عامة.
- **هل Charter724 يخدم مطارات عراقية** (بغداد/النجف الموجودة في الواجهة الحالية)؟ سنعرف من قائمة المطارات الحقيقية.
- **المقاعد:** حقل `capacity` قد يكون مجموع سعات خيارات أخرى (حسب المواصفات)، فالتحقق النهائي يكون عند الحجز لاحقاً.
- **الواجهة الأمامية:** لم تُعدَّل. ونوافذ الـ CSP تحتاج تعديلاً في الخطوة 3 (سياسة `connect-src` الحالية ستحجب نداءات `/api`).

## 9) حل المشاكل
- `EADDRINUSE`: المنفذ مشغول. غيّر `PORT=3001` في `.env`.
- `PROVIDER_LOGIN_FAILED`: تأكد من اسم المستخدم وكلمة المرور في `.env` بلا مسافات زائدة.
- `PROVIDER_UNAUTHORIZED` (-105): التوكن مرفوض. جرّب تسجيل الـ IP كما في البند 5.
- `PROVIDER_UNAVAILABLE`: لا إنترنت أو تعذّر الوصول إلى `api724.ir`.
- `PROVIDER_NOT_CONFIGURED`: في الوضع الحقيقي تأكد من اسم المستخدم وكلمة المرور والرابط في `.env`.
